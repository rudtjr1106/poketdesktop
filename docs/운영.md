# 운영

서버를 돌리면서 알아야 할 것들.

## 무엇이 자동으로 도나

| 워크플로 | 언제 | 하는 일 |
|---|---|---|
| `keepalive` | 5분마다 | 서버를 깨우고, **오류가 많으면 알린다** |
| `backup` | 매일 새벽 3시 17분 | DB 를 떠서 **잠근 뒤** 90일간 보관 |
| `test` | 밀어 넣을 때마다 | 검사를 전부 돌린다 |

공개 저장소라 Actions 분이 무료다. 비공개로 바꾸면 keepalive 의 5분 주기가
월 8,640분이 되어 무료 한도(2,000분)를 넘긴다.

> GitHub 의 cron 은 정확하지 않다. 몰리는 시간대에는 10~30분씩 밀린다.
> 그리고 **60일 동안 커밋이 없으면 예약 실행이 자동으로 꺼진다.**
> 그때는 Actions 탭에서 다시 켜면 된다.

## 처음 한 번 넣어야 하는 것

저장소 **Settings → Secrets and variables → Actions**.

### Secrets (감춰지는 값)

| 이름 | 무엇 |
|---|---|
| `POKET_TURSO_URL` | `libsql://...` — Render 환경변수와 같은 값 |
| `POKET_TURSO_TOKEN` | Turso 토큰 — Render 환경변수와 같은 값 |
| `POKET_BACKUP_KEY` | **백업을 잠글 암호.** 아무 긴 문자열이면 된다 |

**`POKET_BACKUP_KEY` 는 따로 적어 두어야 한다.** 이걸 잃어버리면 백업을
영영 못 연다. GitHub 에 넣은 값은 다시 볼 수 없다.

### Variables (그냥 보이는 값)

| 이름 | 무엇 |
|---|---|
| `POKET_SERVER` | `https://poketdesktop.onrender.com` |
| `POKET_ERROR_LIMIT` | 안 넣으면 10. 한 시간에 이만큼 넘게 오류가 나면 알린다 |

## 오류를 어떻게 아나

예상 못 한 오류는 `server_error` 표에 남고, `/api/health` 가 최근 한 시간
개수를 알려준다. 5분마다 도는 keepalive 가 그걸 보고 많으면 **워크플로를
실패시킨다** — 그러면 GitHub 이 알아서 메일을 보낸다.

감시 장치를 따로 두지 않은 이유는 keepalive 가 이미 돌고 있기 때문이다.

자세한 내용(역추적)은 `/api/health` 에 넣지 않는다. 거기는 인증 없이 누구나
보는 자리라 서버 안쪽 구조가 드러난다. 자세한 건 Render 대시보드의 로그에서
본다.

기록은 48시간이 지나면 서버가 뜰 때 지운다. 진단용이지 보관용이 아니다.

## DB 들여다보기

`deploy/dbview.ps1`(바탕화면 바로가기) 나 `deploy/dbview.sh` 로 열면
sqlite-web 화면 왼쪽에 **Tables** 와 별개로 **Views** 목록이 있다.
`v_` 로 시작하는 것들이 그거다.

| view | 무엇을 보여주나 |
|---|---|
| `v_users` | 가입일·최근 로그인·**마지막 접속**·보유 포켓몬 수 |
| `v_sessions` | 기기별 세션. 어느 계정인지 username 이 같이 나온다 |
| `v_pokemon` | 잡은 시각 + 누구 것인지 |
| `v_friend` / `v_friend_block` | 신청·차단 시각 + 양쪽 닉네임 |
| `v_pvp_match` / `v_battle_record` | 대전 시각. 재생용 로그(`log`/`seed`) 는 뺐다 |
| `v_rank_stat` | 랭킹 갱신 시각 |
| `v_server_error` / `v_login_fail` | 진단용 |

**왜 원본 표(`users` 등)는 그대로 UTC 인가.** 세션 만료·야생 쿨다운·
랭킹 하루 제한 같은 계산이 저장된 문자열끼리 비교하는 방식이라, 저장
형식을 바꾸면 옛 행과 새 행이 섞여 비교가 어긋난다. 그래서 저장은
손대지 않고 **읽기 전용 view** 로만 한국시간(KST, UTC+9)을 보여준다.
`v_users.pokemon_count` 처럼 여러 표를 걸쳐야 하는 값도 view 라서
저장 없이 계산만으로 나온다.

**"마지막 접속"이 무엇인가.** `last_login` 은 로그인한 그 순간이라
그 뒤로 몇 시간을 켜 뒀는지는 안 담는다. 이 게임은 켜져 있는 동안
90초마다 서버를 두드리므로(`syncSeconds`), 세션들의 최근 `last_seen`
중 가장 늦은 것이 "언제까지 떠 있었는가" 에 가장 가깝다 - 앱을 끄는
순간 서버에 알리는 절차가 없어서(폴링 구조라 그런 신호 자체가 없다)
정확한 "종료 시각"은 아니고, 실제로는 그보다 최대 90초쯤 이르다.

view 는 CREATE VIEW 문일 뿐 데이터가 없어서, 서버가 뜰 때마다 지우고
다시 만든다(`server/app/db.py` 의 SCHEMA). 정의를 바꾼 다음 판이
나가면 재배포만으로 반영된다 - 따로 손볼 것이 없다.

## 백업

### 왜 잠그나

백업에는 **닉네임과 비밀번호 해시**가 들어 있다. 이 저장소는 공개라
Actions 아티팩트도 누구나 받아 갈 수 있다. 비밀번호가 숫자 네 자리라
해시가 새어 나가면 오프라인에서 만 번만 돌려도 뚫린다.

그래서 올리기 전에 반드시 `openssl` 로 잠근다. 열쇠가 없으면 백업을
아예 만들지 않는다 — 잠그지 않은 채로 올리느니 안 하는 게 낫다.

워크플로는 매번 **다시 열어 보고** 나서 올린다. 열리지 않는 백업은
백업이 아니다.

### 되살리기

```bash
# 1. 받는다 (실행 번호는 Actions 탭에서 확인)
gh run download <실행번호> -n backup-<번호>

# 2. 연다
set POKET_BACKUP_KEY=적어둔_암호
openssl enc -d -aes-256-cbc -pbkdf2 -iter 200000 ^
        -in backup.sql.enc -out backup.sql -pass env:POKET_BACKUP_KEY

# 3. 되살린다 (지금 들어 있는 것을 덮어쓴다)
set POKET_TURSO_URL=libsql://...
set POKET_TURSO_TOKEN=...
python tools/restore_db.py --in backup.sql
```

되살리기는 **스키마를 만들지 않는다.** 표가 없으면 서버를 한 번 띄워서
만들게 한 뒤에 돌려야 한다. 백업이 스키마까지 들고 있으면 그 사이 바뀐
칸을 놓친다.

### 손으로 떠내기

```bash
set POKET_TURSO_URL=libsql://...
set POKET_TURSO_TOKEN=...
python tools/backup_db.py --out backup.sql
```

이건 잠기지 않은 파일이다. 다 쓰고 나면 지워야 한다.

## 서버가 왜 느린가

재보니 이랬다.

| | |
|---|---|
| DB 를 **안 쓰는** 요청 | 220ms |
| 쿼리 **하나**당 | 100~200ms |
| 같은 코드, 로컬 | 3~31ms |

코드가 느린 게 아니라 **왕복이 비싸다.** Render 는 싱가포르, Turso 는
도쿄(`aws-ap-northeast-1`) 라 쿼리마다 바다를 건넌다.

### 지역을 맞출 수는 없다

한 번 알아보고 포기한 길이라 적어 둔다. **다시 시도하지 마라.**

| 시도 | 왜 안 되나 |
|---|---|
| Turso 를 싱가포르로 | **Turso 에 싱가포르가 없다.** 지역은 도쿄·뭄바이·아일랜드·버지니아·오하이오·오리건뿐이다. 아시아는 도쿄가 유일하다 |
| 그룹 위치를 바꾸기 | 위치는 DB 가 아니라 **group** 에 붙는다. `turso group update` 에 위치 옵션이 없다 |
| 다른 지역에 group 을 새로 | 무료 등급은 **group 이 하나뿐**이다 |
| Render 를 도쿄로 | Render 리전은 오리건·오하이오·버지니아·프랑크푸르트·싱가포르 다섯뿐이라 **도쿄가 없다.** 게다가 이미 만든 서비스는 리전을 못 바꾼다 |

그래서 답은 "DB 를 옮긴다" 가 아니라 **"왕복을 줄이거나 없앤다"** 다.

### 할 수 있는 것

1. **쿼리 횟수 줄이기.** 이미 한 번 했다 - `/api/me` 8회→5회, `/api/shop`
   5회→3회. 1.5~2배 빨라졌다. 위험 없고 언제 해도 손해가 없다.

2. **붙박이 복제본(embedded replica).** `db.py` 에 분기는 이미 있고 꺼져 있다
   (`POKET_TURSO_REPLICA`). 켜면 읽기가 로컬 파일에서 끝나 왕복이 사라진다.
   **다만 그냥 켜면 안 된다** - 아래 "켜기 전에 고쳐야 할 것" 을 보라.

3. **서버 한 대에 SQLite 파일.** 왕복이 0 이 된다. 코드는 안 고쳐도 된다 -
   `POKET_TURSO_URL` 을 비우면 `db.py` 가 알아서 `POKET_DB` 경로의 로컬
   sqlite3 로 붙는다. 서울에 한 대 두면 한국 사용자와의 거리도 같이 준다.
   대신 직접 운영해야 하고 디스크 백업이 내 몫이 된다.

### 붙박이 복제본을 켜기 전에 고쳐야 할 것

지금 켜면 **틀린 값이 나온다.** 확인한 것들:

- `_open()` 이 복제본을 만들기만 하고 **`sync()` 를 아무도 안 부른다.**
  다른 곳(도구 스크립트 등)에서 쓴 것이 서버에 영영 안 보인다.
  `libsql.connect(..., sync_interval=60)` 을 같이 줘야 한다.
- `db.py` 는 **스레드마다 커넥션을 따로 연다**(`threading.local`).
  복제본을 켜면 같은 파일을 여러 스레드가 각각 연다. Turso 문서는
  동기화 중에 로컬 DB 를 또 여는 것을 **자료 손상** 위험으로 경고한다.
  이 조합이 안전한지는 확인하지 못했다. **시험용 서버에서 먼저 돌려 보라.**
- 재시작하면 복제본 파일이 날아가서 처음에 DB 전체를 다시 받는다.
  지금은 자료가 작아서 상관없지만 커지면 다시 봐야 한다.

## DB 를 다른 곳으로 옮기기

`tools/move_db.py` 가 떠내기·표 만들기·넣기·대조를 한 번에 한다.
스키마를 `db.SCHEMA` 에서 그대로 가져오므로 **받는 쪽에 서버를 먼저 붙일
필요가 없다.** 보내는 쪽은 건드리지 않아서 언제든 되돌아갈 수 있다.

Turso 사이는 물론이고 **그냥 파일로도 뽑을 수 있다** - 서버 한 대에
SQLite 로 옮길 때 쓰면 된다. 뽑은 파일이 파이썬 기본 `sqlite3` 로
열리는 것과 BLOB(비밀번호 해시)이 그대로인 것은 확인했다.

```bat
set POKET_FROM_URL=libsql://지금-쓰는-것...
set POKET_FROM_TOKEN=지금-토큰
set POKET_TO_URL=libsql://새-DB...     :: 또는 그냥  D:\poket.db
set POKET_TO_TOKEN=새-토큰             :: 파일이면 아무 값이나
python tools/move_db.py
```

끝에 양쪽 행 수를 나란히 보여준다. **하나라도 다르면 멈추고 아무것도
바꾸지 마라.** 보내는 쪽은 그대로다.

옮긴 뒤에 할 일:

1. Render 환경변수(`POKET_TURSO_URL`, `POKET_TURSO_TOKEN`)를 바꾼다.
   파일로 갔다면 대신 `POKET_DB` 를 주고 두 값을 **지운다.**
2. **GitHub Secrets 도 같이 바꾼다.** 안 바꾸면 백업이 옛 DB 를 계속 뜬다.
3. 옛 DB 는 며칠 그대로 둔다. 되돌아갈 곳이다.

**옮기는 동안 게임을 켜 두지 마라.** 그 사이에 쓴 것은 사라진다.

남는 `move-backup.sql` 에는 닉네임과 비밀번호 해시가 들어 있다. 다 쓰면
지워라. (`.gitignore` 가 `*.sql` 을 막아서 실수로 커밋되지는 않는다.)
