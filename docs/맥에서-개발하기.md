# 맥에서 개발하기

맥북에서 이 게임을 돌리고 고치기 위한 안내다.

> **읽는 법**
>
> 이 문서에는 두 종류가 섞여 있다.
>
> - **[확인함]** — 윈도우에서 실제로 코드를 읽거나 돌려서 확인한 것.
>   줄 번호는 v1.0.8 기준이다.
> - **[확인 못 함]** — 맥이 없어서 문서와 경험으로만 적은 것. **맥에서
>   직접 해 보고 다르면 이 문서를 고쳐라.** 특히 3장의 맥 API 부분이다.
>
> 되는 척하는 것보다 모르는 것을 모른다고 적는 편이 낫다.

---

## 0. 먼저 알아 둘 것

**크로스 빌드는 안 된다.** 맥용 `.app` 은 맥에서만 만들어진다. 윈도우에서
맥 빌드를 뽑을 방법이 없으니, 맥 작업은 전부 맥에서 해야 한다.

**서버는 하나를 같이 쓴다.** 맥 클라이언트를 만들어도 서버는 그대로다.
윈도우 유저와 맥 유저가 친구가 되고 PvP 도 된다 — 대전은 서버가 계산한다.

## 2. 준비하고 일단 돌려보기

### 파이썬과 tkinter

**맥의 파이썬은 tkinter 가 따로 붙는다.** 이걸 모르면 `import tkinter` 에서
바로 막힌다.

```bash
brew install python@3.12 python-tk@3.12
```

시스템에 딸려 오는 `/usr/bin/python3` 은 쓰지 마라. tkinter 가 옛 Tk 8.5 에
묶여 있어서 한글과 투명 처리에서 이상하게 군다. `python3 -m tkinter` 를 쳐서
창이 뜨고, 그 창에 적힌 Tk 버전이 **8.6 이상**인지 확인해라.

### 받아서 띄우기

```bash
git clone https://github.com/rudtjr1106/poketdesktop.git
cd poketdesktop
python3 -m venv .venv
source .venv/bin/activate
pip install -r client/requirements.txt
```

```bash
POKET_HOME=~/poket-dev python3 client/run.pyw
```

**`POKET_HOME` 을 꼭 붙여라.** 안 붙이면 실제 계정의 설정과 로그인을
건드린다. 시험용 계정을 따로 만들어 쓰는 편이 낫다.

### 여기서 터지는 것이 곧 할 일 목록이다

로그는 `~/poket-dev/poketdesktop.log` 에 쌓인다. 처음에는
`-transparentcolor` 에서 `TclError` 가 날 것이다 — 그게 3장의 첫 번째다.

## 3. 진짜 막히는 것 셋

### (1) 투명 배경 — 핵심

포켓몬이 바탕화면 위에 **네모난 창 없이** 떠 있는 것이 이 게임의 전부다.

**[확인함]** 지금은 `-transparentcolor` 로 한다. 특정 색(마젠타)을 칠해 두면
윈도우가 그 색만 뚫어 준다. **이 옵션은 윈도우 전용이다.**

거기 걸린 곳:

| 파일 | 줄 | 무엇 |
|---|---|---|
| `client/poketdesktop/overlay.py` | 61 | 포켓몬 도트 창 |
| `client/poketdesktop/wild_ui.py` | 47, 255 | 풀숲과 야생 포켓몬 |
| `client/poketdesktop/fx_layer.py` | 54 | 배틀 이펙트 레이어 |
| `client/poketdesktop/evolve_fx.py` | 139 | 진화 연출 |

**[확인 못 함]** 맥에는 대신 `-transparent` 가 있다. **방식이 다르다** —
윈도우는 "이 색을 뚫어라" 이고, 맥은 "창 배경 자체를 투명하게" 다.

```python
# 윈도우 (지금)
win.attributes("-transparentcolor", hexkey)
canvas.configure(bg=hexkey)          # 이 색이 뚫린다

# 맥 (해 봐야 안다)
win.attributes("-transparent", True)
win.configure(bg="systemTransparent")
canvas.configure(bg="systemTransparent")
```

> **맥이 오히려 나은 점이 하나 있다.**
>
> `evolve_fx.py` 의 주석은 "창마다 투명색이 하나뿐이라" 고생한 이야기다.
> 도트 안에 마젠타가 들어 있으면 그 부분이 구멍처럼 뚫린다. 맥은 색으로
> 뚫는 방식이 아니라서 **이 문제 자체가 없어진다.** 우회 코드를 지울 수
> 있을지 확인해 봐라.

**확인할 것**: 도트 뒤로 바탕화면이 보이는가. 도트 자체의 색이 잘못 뚫리지
않는가. 창 그림자(맥은 창에 그림자를 붙인다)가 도트 주위에 남지 않는가 —
남으면 `win.attributes("-transparent", True)` 만으로는 모자라고 NSWindow 의
`hasShadow` 를 꺼야 할 수 있다.

### (2) 클릭 통과 — 제일 지저분하다

**[확인함]** `client/poketdesktop/fx_layer.py:16` 의 `make_click_through()`
가 이펙트 레이어를 마우스가 그냥 통과하게 만든다. 이게 없으면 이펙트가 뜬
동안 바탕화면 아이콘을 못 누른다. 윈도우에서는 `WS_EX_TRANSPARENT` 라는
확장 스타일 한 줄이다.

**[확인 못 함]** 맥에도 같은 것이 있다 — NSWindow 의 `ignoresMouseEvents`.
**다만 Tk 에서 직접 못 건드린다.** pyobjc 로 NSWindow 를 붙잡아야 한다.

```bash
pip install pyobjc-framework-Cocoa
```

문제는 **어느 NSWindow 가 내 Tk 창인지 찾는 것**이다. `NSApp.windows()` 를
순회하며 크기나 위치로 맞추는 방법이 흔히 쓰이는데, 창이 여럿이면 헷갈린다.

> **여기가 실패하면 레이어를 아예 안 띄우는 쪽이 낫다.**
>
> 클릭 통과가 안 되는 이펙트 레이어는 화면 전체를 덮는 투명한 벽이 된다.
> 바탕화면 아이콘도, 다른 프로그램도 못 누른다. **이펙트가 안 보이는 것보다
> 훨씬 나쁘다.** `make_click_through()` 가 False 를 돌려주면 레이어를
> 만들지 않도록 부르는 쪽을 고쳐 두는 편이 안전하다.

### (3) 트레이 아이콘 — 띄워 봐야 안다

**[확인함]** `client/poketdesktop/tray.py` 의 첫 주석이 이렇게 적혀 있다:

> pystray 는 자기 스레드에서 도는데 tkinter 는 다른 스레드에서 만지면 안 된다.

**[확인 못 함]** pystray 는 맥을 지원한다고 돼 있지만, 맥에서는 **아이콘을
메인 스레드에서 돌려야 한다**(AppKit 제약). 그런데 tkinter 도 메인 스레드를
쓴다. 위 전제가 맥에서는 깨진다.

띄워 보고 안 되면 두 갈래다.

- **`rumps`** — 맥 메뉴바 전용 라이브러리. 더 맥답게 보인다. 다만 이것도
  메인 스레드 문제가 있어서 tkinter 와 어떻게 엮을지 설계가 필요하다.
- **작은 창으로 대체** — 트레이를 포기하고 항상 떠 있는 작은 창으로.
  가장 확실하지만 화면을 차지한다.

트레이는 이 게임의 유일한 메뉴다(포켓몬 관리·가방·상점·설정이 전부 거기서
열린다). 여기가 막히면 게임을 조작할 방법이 없으니, **(1) 투명 배경 다음으로
중요하다.**

## 5. 권하는 순서

1. **그냥 돌려서 터지는 것을 다 적는다.** 로그를 보면서.
2. **폰트** — 제일 쉽고, 고치면 화면이 곧바로 읽을 만해진다.
3. **투명 배경** — 이게 되면 게임이 눈에 보인다. 여기까지가 반이다.
4. **트레이** — 이게 되면 조작이 된다.
5. **클릭 통과** — 안 되면 레이어를 끄는 쪽으로 타협.
6. **작업 영역** (메뉴 막대·독 피하기), **자동 시작**.
7. **빌드와 배포.**

## 6. 코드를 어떻게 나눌까

지금은 윈도우 전용 코드가 일곱 파일에 흩어져 있다. 맥 코드를 그 옆에 `if`
로 덧붙이면 두 배로 헝클어진다.

**`platform_win.py` / `platform_mac.py` 로 가르는 것을 권한다.** 다섯 가지만
숨기면 된다.

```python
# platform_base.py 가 정하는 계약
def make_transparent(win, hexkey)   # 창 배경을 뚫는다
def make_click_through(win)         # 마우스를 통과시킨다 (성공 여부 반환)
def work_area(w, h)                 # 쓸 수 있는 화면 (작업표시줄/독 제외)
def single_lock(data_dir)           # 중복 실행 막기
def default_font()                  # 기본 글꼴 이름
```

> **윈도우 동작을 깨뜨리지 마라.**
>
> 지금 쓰는 사람이 있다. 코드를 옮기는 것은 좋지만 **같은 코드가 그대로
> 옮겨가야 한다.** 옮긴 뒤 윈도우에서 검사를 다시 돌려서 전부 통과하는지
> 확인해라. 옮기면서 "겸사겸사" 고치지 마라 — 뭐가 깨졌는지 못 찾는다.

## 7. 검사

**화면 없이 도는 것** — 맥에서 지금 바로 된다.

```bash
python3 client/test_layout.py        # 투기장 좌표 3,294개
python3 common/test_korean.py        # 시간 표기 70,774개
python3 client/test_battle_ui.py     # 체력바 22개
```

**윈도우 전용** — 맥에서는 "윈도우에서만 하는 검사입니다" 하고 그냥 넘어간다.

```bash
python3 client/test_autostart.py
python3 client/test_boot_retry.py    # 이건 맥에서도 돈다
python3 client/smoke_autostart.py    # 화면 필요 + 윈도우 전용
```

**서버 검사** — 도커로 임시 서버를 띄워서 돌린다.

```bash
docker build -f server/Dockerfile -t poket-test .
docker run -d --name poket-test -p 8788:8080 \
  -e POKET_DB=/data/poket.db -e POKET_POKEDEX=/app/data/pokedex.json \
  -e POKET_REQUIRE_IP=0 poket-test
python3 server/test_social.py http://127.0.0.1:8788
```

> **운영 서버(`posktop.duckdns.org`)에 검사를 돌리지 마라.** 계정을 만들고
> 지우고 배틀을 거는 검사들이다. 실제 사용자 데이터가 있는 곳이다.

`server/test_items.py` 는 지금도 7개가 실패한다. **원래 그렇다** — 야생 배틀
승리를 전제로 하는 검사들이라 환경을 탄다. 맥 때문이 아니다.

## 8. 배포는 나중 이야기

PyInstaller 가 `.app` 번들을 만들어 준다. 다만 **서명이 없으면** 받는 사람이
"확인되지 않은 개발자" 경고를 만난다. 우클릭 → 열기로 우회할 수 있지만,
윈도우의 SmartScreen 과 같은 종류의 마찰이다.

제대로 하려면 애플 개발자 등록(연 $99)과 공증(notarization)이 필요하다.
안 할 거라면 README 에 우회법을 적어 두면 된다 — 윈도우 쪽에 이미 그렇게
적어 뒀다(`docs/defender-false-positive.md` 참고).

## 9. 하지 말 것

- **윈도우 코드를 지우고 맥 코드로 바꾸지 마라.** 둘 다 살아 있어야 한다.
  지금 윈도우에서 쓰는 사람이 있다.
- **`POKET_HOME` 없이 돌리지 마라.** 실제 계정의 설정과 로그인이 덮인다.
- **운영 서버에 검사를 돌리지 마라.**
- **되는 척하지 마라.** 맥에서 아직 안 되는 것은 화면에서 "아직 안 됩니다"
  라고 말해야 한다. `autostart.py` 가 그렇게 해 두었으니 그 방식을 따라라.
