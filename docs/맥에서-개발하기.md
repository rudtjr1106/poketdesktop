# 맥에서 개발하기

맥북에서 이 게임을 돌리고 고치기 위한 안내다.

> **읽는 법**
>
> - **[확인함]** — 이 맥(macOS 26.5.2, Apple Silicon, Tk 8.6.17)에서 실제로
>   돌려서 확인한 것. 대부분 검사 코드로 남겨 두었으니 다시 돌려볼 수 있다.
> - **[눈으로 봐야 함]** — 코드는 들어갔지만 사람이 화면을 봐야 확정되는 것.
>
> 되는 척하는 것보다 모르는 것을 모른다고 적는 편이 낫다.

---

## 0. 지금 상태

**맥에서 돌아간다.** 도트가 바탕화면을 걸어다니고, 메뉴 막대에 몬스터볼
아이콘이 뜨고, `.app` 으로 묶어서 배포할 수 있다.

윈도우 코드는 그대로 살아 있다. 다른 것만 `platform_win.py` /
`platform_mac.py` 로 갈라 두었고, 부르는 쪽은 `platform_os` 하나만 본다.

**크로스 빌드는 여전히 안 된다.** 맥용 `.app` 은 맥에서만 만들어진다.

**서버는 하나를 같이 쓴다.** 윈도우 유저와 맥 유저가 친구가 되고 PvP 도
된다 — 대전은 서버가 계산한다.

## 1. 준비하고 돌려보기

### 파이썬과 tkinter

**맥의 파이썬은 tkinter 가 따로 붙는다.** 이걸 모르면 `import tkinter` 에서
바로 막힌다. 둘 중 하나면 된다.

```bash
brew install python@3.12 python-tk@3.12
```

또는 [python.org 설치본](https://www.python.org/downloads/macos/)을 쓴다
(Tk 8.6 이 같이 들어 있다. 이쪽이 손이 덜 간다).

시스템에 딸려 오는 `/usr/bin/python3` 은 쓰지 마라. Tk 8.5 에 묶여 있다.
`python3 -m tkinter` 를 쳐서 창에 적힌 Tk 버전이 **8.6 이상**인지 봐라.

### 받아서 띄우기

```bash
git clone https://github.com/rudtjr1106/poketdesktop.git
cd poketdesktop
python3 -m venv .venv
source .venv/bin/activate
pip install -r client/requirements.txt
```

`client/requirements.txt` 에 **pyobjc 가 들어 있다** (맥에서만 설치된다).
이게 없으면 투명 배경도 메뉴 막대 아이콘도 안 된다 — 도트가 네모난 판
위에 뜨고, 게임을 조작할 방법이 없어진다.

```bash
POKET_HOME=~/poket-dev python3 client/run.pyw
```

**`POKET_HOME` 을 꼭 붙여라.** 안 붙이면 실제 계정의 설정과 로그인을
건드린다. 로그는 `~/poket-dev/poketdesktop.log` 에 쌓인다.

### 서버를 손에 두고 시험하기

**운영 서버(`posktop.duckdns.org`)에 검사를 돌리지 마라.** 계정을 만들고
지우고 배틀을 거는 검사들이고, 실제 사용자 데이터가 있는 곳이다.

도커가 있으면 7장을 보고, 없으면 그냥 띄워도 된다.

```bash
python3 -m venv .venv-server
.venv-server/bin/pip install fastapi 'uvicorn<1.0' 'pydantic<3.0'
cd server
PYTHONPATH=.. POKET_DB=/tmp/poket.db \
POKET_POKEDEX=$PWD/data/pokedex.json POKET_REQUIRE_IP=0 \
POKET_SPRITE_DIR=/tmp/sprites POKET_WALK_DIR=/tmp/walk \
../.venv-server/bin/python -m uvicorn app.main:app --port 8788
```

그 다음 클라이언트를 `POKET_SERVER=http://127.0.0.1:8788` 로 띄운다.
도트는 서버가 PokeAPI 에서 받아 `POKET_SPRITE_DIR` 에 캐시한다. 못 받으면
`0001.gif` 같은 이름으로 직접 넣어 줘도 된다.

## 2. 어디가 어떻게 다른가

윈도우 전용 코드가 일곱 파일에 흩어져 있던 것을 두 파일로 모았다.

```
platform_base.py    계약. 어느 쪽도 아닐 때 쓸 기본 구현 (리눅스)
platform_win.py     윈도우. 원래 있던 코드를 그대로 옮겼다
platform_mac.py     맥
platform_os.py      이 컴퓨터에 맞는 것을 고른다. 부르는 쪽은 이것만 본다
tray_mac.py         맥 메뉴 막대 아이콘 (pystray 를 못 써서 따로 있다)
```

숨긴 것은 이렇다.

| | 윈도우 | 맥 |
|---|---|---|
| 투명 배경 | `-transparentcolor` (색을 뚫는다) | `-transparent` + CALayer |
| 클릭 통과 | `WS_EX_TRANSPARENT` | NSWindow `ignoresMouseEvents` |
| 작업 영역 | `SystemParametersInfoW` | `NSScreen.visibleFrame` |
| 중복 실행 | 이름 있는 뮤텍스 | `flock` |
| 더블클릭 | `GetDoubleClickTime` (보통 500ms) | `NSEvent.doubleClickInterval` (500ms) |
| 기기 ID | 레지스트리 `MachineGuid` | `gethostuuid` (안 되면 `ioreg`) |
| 저장 위치 | `%APPDATA%\poketdesktop` | `~/Library/Application Support/poketdesktop` |
| 자동 시작 | 레지스트리 `Run` 키 | `~/Library/LaunchAgents` 의 plist |
| 자동 업데이트 | zip 을 풀어 옆 폴더에 | dmg 에서 `.app` 을 꺼내 갈아끼운다 |
| 트레이 | pystray | `NSStatusItem` 아이콘 + tkinter 로 그린 메뉴 |
| 뜨는 메뉴 | `tk.Menu` | `ui_common.PopupMenu` (tk.Menu 는 NSMenu 라 못 쓴다) |
| 대화창 소속 | `win.transient(root)` | `PLAT.own_dialog` — 맥은 **안 건다** (걸면 창이 사라진다) |
| 오른쪽 클릭 | `<Button-3>` | Tk 을 안 거치고 Cocoa 감시자로 직접 받는다 |
| 휠 한 칸 | delta 120 | **delta 1~3** (`ui_common.wheel_units`) |
| 작업표시줄/Dock | 원래 안 뜬다 | `LSUIElement` + `setActivationPolicy` |
| 기본 글꼴 | 맑은 고딕 | Apple SD Gothic Neo |
| 빌드 | `tools/build_exe.py` | `tools/build_app.py` |

## 3. 맥에서 물렸던 것들

여기 적힌 것은 전부 **실제로 물린 것**이다. 고치면서 지나간 순서대로다.

### (1) 투명 배경 — Tk 은 투명 위젯에 그림을 못 그린다

**[확인함]** 맥 Tk 에 `-transparentcolor` 는 **아예 없는 속성**이다
(`TclError`). 대신 `-transparent` 가 있고, 이걸 걸면 NSWindow 가
`isOpaque=False`, 배경 `clearColor`, **`hasShadow=False`** 가 된다 —
창 그림자까지 알아서 꺼진다.

**그런데 여기서 끝이 아니다.** 배경이 `systemTransparent` 인 위젯에
그림을 올리면 Tk 이 **아무것도 안 그린다.** Label 이든 Canvas 든,
`ImageTk` 든 `tk.PhotoImage` 든, 알파가 있든 없든 똑같다. 예외도 안 난다.
글자와 선(`create_text`, `create_rectangle`)은 멀쩡히 그려지는데 **그림만**
사라진다.

즉 `-transparentcolor` 를 `-transparent` 로 바꾸기만 하면 **포켓몬이
통째로 안 보이는 빈 창**이 된다.

그래서 맥에서는 **창과 좌표와 마우스만 Tk 이 맡고, 도트는 CALayer 가
그린다** (`platform_mac.SpriteView`).

**얻는 것** — 색으로 뚫는 방식이 아니라서 `evolve_fx.py` 가 고생하던
"도트 안에 자홍색이 있으면 구멍이 뚫린다" 는 문제가 없어졌다.

**잃을 뻔한 것** — 도트 둘레의 투명한 자리가 클릭을 먹는다. 윈도우에서는
뚫린 픽셀로 클릭이 그대로 지나가는데, 맥에서는 도트 바운딩 박스만큼
보이지 않는 네모가 바탕화면 클릭을 가로챈다. 풀숲 창은 면적의 60% 가
그런 자리다.

이유는 알파가 아니다. **맥 창 서버는 알파가 0 인 자리로 클릭을 잘
통과시킨다** — 똑같이 설정한 순수 NSWindow 로는 통과한다. 통과를 막는
것은 Tk 의 `TKWindow` 다. 창 레벨도 styleMask 도 contentView 도 바꿔
봤지만 안 돌아온다. 그래서 Tk 창에서 클릭을 통과시키는 수단은
`ignoresMouseEvents` 하나뿐인데, 그건 창 **전체**에 걸린다.

**커서를 좇아가며 켜고 끄는 것으로 고쳤다.** 도트를 만들 때 알파 마스크를
같이 들고 있다가(`platform_mac.Frame.mask`), 오버레이가 매 틱마다 커서
밑 픽셀이 비었는지 보고 `ignoresMouseEvents` 를 바꾼다
(`SpriteView.update_hit`). 마스크는 여섯 마리에 1MB 남짓이다.

한 가지 규칙이 있다. **커서가 창 밖이면 도로 막아 둔다.** 창 서버에
반영되기까지 한 틱쯤 걸리는데, 밖에 있을 때 통과 상태로 두면 커서가
도트로 들어온 직후의 클릭이 바탕화면으로 새어 나간다. 포켓몬을 못
누르는 것이 빈 자리를 못 누르는 것보다 나쁘다.

같이 물린 것 둘:

- **`CATransaction.setDisableActions_(True)` 를 안 걸면** 프레임을 바꿀
  때마다 CoreAnimation 이 0.2초짜리 크로스페이드를 붙인다. 걷기가 90ms
  간격이라 동작이 통째로 뭉개진다.
- **`-topmost` 는 창이 화면에 올라간 뒤에 걸어야 먹는다.** 만들자마자
  걸면 조용히 씹힌다. 이름표만 다른 창 뒤로 숨는 식으로 나타난다.
  그래서 `PLAT.raise_above(win)` 가 따로 있고, 창을 만드는 자리마다
  마지막에 부른다.

검사: `python client/smoke_mac.py [도트.gif]` — 창을 띄우고 **화면에
합성된 결과를 그대로 읽어서** 모서리가 투명한지, 도트가 그려졌는지,
투명색이 새지 않는지, 프레임이 바뀌는지를 본다.

### (2) 클릭 통과 — NSWindow 를 확실하게 찾는 법

**[확인함]** 맥은 NSWindow 의 `ignoresMouseEvents` 인데 Tk 에서 직접 못
건드린다. 문제는 **어느 NSWindow 가 내 Tk 창인지 찾는 것**이다.

`NSApp.windows()` 를 돌며 제목이나 크기로 맞추는 방법은 **틀린 것을
잡는다** — 테두리 없는 창은 제목이 전부 같고 같은 크기 창도 흔하다.

확실한 길이 있다. Tk 이 내보내는 `TkMacOSXGetRootControl` 을 ctypes 로
불러 `winfo_id()` 를 NSView 로 바꾸고, 거기서 `.window()` 를 얻는다.
포인터를 따라가는 것이라 틀릴 수가 없다. (`winfo_id()` 자체는 NSView 가
아니라 Tk 내부 구조체다.) `update_idletasks()` 를 먼저 불러야 한다 —
안 그러면 NULL 이 온다.

**함정:** `deiconify()` 를 부르면 Tk 이 창 속성을 다시 걸면서 이 플래그를
**푼다.** 숨겼다 켠 뒤가 아니라 그냥 부르기만 해도 풀린다. 그래서
`FxLayer.raise_above()` 가 매번 다시 확인한다.

**못 걸면 레이어를 아예 안 만든다** (`fx_layer.open_layer` 가 None).
통과하지 않는 투명 레이어는 화면을 덮는 보이지 않는 벽이라, 이펙트가
안 보이는 것보다 훨씬 나쁘다.

**[확인함]** 마우스가 실제로 레이어를 지나 아래 창으로 가는 것까지
확인했고, 검사로 남겨 두었다(`smoke_mac.py`). 창 서버에 "이 좌표에서
마우스를 받을 창이 어디냐" 고 직접 물어보는 방식이라 사람 손이 필요 없다.
통과를 껐다 켰다 하는 대조 실험도 같이 들어 있다.

한 가지 알아둘 것: 플래그를 바꾼 뒤 창 서버에 반영되려면 **이벤트 루프가
돌아야 한다.** 그냥 기다리는 것으로는 안 바뀐다. 보통 20~30ms 다.

### (3) 트레이 — pystray 도, NSMenu 도 못 쓴다

**[확인함]** pystray 의 맥 백엔드는 `NSApplication.run()` 을 부른다.
그걸 별도 스레드에서 부르면 **파이썬 예외도 못 남기고 SIGTRAP 으로
즉사한다.** tkinter 도 메인 스레드를 쓰니 자리를 비켜 줄 수도 없다.

Tk aqua 의 `mainloop` 는 이미 Cocoa 메인 런루프를 돌리고 있으니
`NSStatusItem` 을 같은 스레드에서 그냥 만들면 되겠다 싶었다. 아이콘은
그렇게 잘 올라갔다. **그런데 거기에 `NSMenu` 를 붙이면 앱이 죽는다.**

#### NSMenu 가 왜 죽이는가

메뉴가 열리면 macOS 가 **중첩 런루프**(메뉴 트래킹)를 돌린다. 그 동안
Tk 의 `after` 타이머는 계속 발화하는데, 그 경로가 깨져 있다.

    Fatal Python error: PyEval_RestoreThread: the function must be called
    with the GIL held ... (the current Python thread state is NULL)

**메뉴를 열기만 해도 죽는다.** 항목을 안 눌러도 그렇다. 최소 재현으로
좁혀 본 결과가 이렇다.

| 무엇을 했나 | 결과 |
|---|---|
| 메뉴 열기 (Tk 타이머 없음) | 산다 |
| 메뉴 열고 항목 누르기, 콜백은 아무것도 안 함 | 산다 |
| 메뉴 열고 항목 누르기, 콜백이 `root.after()` 호출 | **죽는다** |
| 메뉴 **열기만**, 그 동안 Tk `after` 타이머가 돎 | **죽는다** |

마지막 줄이 핵심이다. 이 게임은 도트를 움직이려고 `after` 를 쉬지 않고
도니, **메뉴를 여는 순간이 곧 마지막**이다. 콜백을 큐로 미뤄도 소용없다 —
문제는 콜백이 아니라 트래킹 중에 도는 Tk 타이머 자체다.

#### `tk.Menu` 도 같은 것이다

`tk.Menu` 는 aqua 에서 그냥 NSMenu 다. 그래서 뜨는 메뉴가 전부 같은
문제를 갖는다 — 포켓몬 오른쪽 클릭 메뉴(`app.pet_menu`)와 볼 고르는
메뉴(`ball_menu.popup`) 둘 다. **맥에서는 `tk.Menu` 를 아예 쓰지 마라.** `platform_os.NATIVE_MENU` 가 False 면
`ui_common.PopupMenu` 로 그린다.

#### 그래서 메뉴를 직접 그린다

메뉴 막대에는 **아이콘(단추)만** 올리고 `setMenu_` 를 부르지 않는다.
단추가 눌리면 그 사실만 적어 두고, Tk 쪽에서 도는 `_pump` 가 꺼내서
**tkinter 로 그린 메뉴 창**을 띄운다. 이 게임은 원래 창을 전부 tkinter 로
그리므로 생김새도 오히려 잘 맞는다. 중첩 런루프가 없으니 안 죽는다
(도트가 도는 중에 열두 번 여닫아도 멀쩡한 것까지 확인했다).

그리는 것은 `ui_common.PopupMenu` 가 한다. 트레이 메뉴와 포켓몬 오른쪽
클릭 메뉴가 같은 것을 쓴다. 하위 메뉴는 따로 띄우지 않고 제목 +
들여쓰기로 편다 - 작은 창 하나에 다 보이는 편이 낫다. 바깥을 누르면
닫히도록 화면을 덮는 거의 안 보이는 창(`-alpha 0.01`)을 뒤에 깐다.

메뉴에 무엇이 들어가는지는 `tray.TrayBase.spec()` **한 곳에만** 있다.
윈도우(pystray)와 맥(tkinter)이 그걸 각자 그린다. 두 벌로 적어 두면
한쪽만 고치는 날이 온다.

지켜야 할 것:

- **`tkinter.Tk()` 를 무조건 먼저 만든다.** 그 전에
  `NSApplication.sharedApplication()` 이 불리면 Tk 이 abort 한다.
- **objc 콜백 안에서 tkinter 를 부르지 않는다.** 눌렸다는 것만 적어 두고
  Tk 쪽에서 꺼내 쓴다.
- **메뉴를 통째로 지우고 다시 만들지 않는다.** 만들다 터지면 반쯤 지어진
  메뉴가 남는데, 하필 '종료' 가 맨 아래라 제일 먼저 사라진다. 메뉴막대가
  유일한 입구인데 종료가 없어지면 끌 방법이 없다.

검사: `python client/test_tray_mac.py` — 상태 아이콘에 **NSMenu 가 안
붙어 있는지**부터 본다. 그게 이 장 전체를 지키는 검사다.

### (4) 입력 — 실제로 써 보고서야 드러난 것 셋

앞의 셋은 코드를 읽어서 찾았고, 아래 셋은 **직접 써 보고서야** 나왔다.

#### 오른쪽 클릭이 통째로 안 먹었다

두 가지가 겹쳐 있었다.

1. **맥 Tk 은 오른쪽 단추가 2번이다.** 3번은 가운데 단추다.
   `<Button-3>` 만 걸어 둔 자리가 조용히 죽어 있었다.
2. 그걸 고쳐도 **앱이 활성이 아니면 Tk 이 오른쪽 클릭을 위젯에 전달하지
   않는다.** 맥이 우리 앱에 주기는 한다(Cocoa 로컬 감시자에는 찍힌다)
   — 거기서 멎는다. 이 게임은 Dock 에 안 뜨는 앱이라 거의 늘 비활성이라,
   **포켓몬을 한 번 왼쪽 클릭해 앱을 깨우기 전에는 우클릭이 안 됐다.**

`acceptsFirstMouse:` 를 붙여도 오른쪽 클릭에는 소용이 없었다. 그래서
`platform_mac.watch_right_click()` 이 Cocoa 단계에서 직접 받고,
`App._right_click_at` 이 그 자리에 있는 도트에게 넘긴다. 맥에서는 Tk 쪽
바인딩을 **아예 걸지 않는다** — 둘 다 걸리면 한 번 누른 것이 두 번
처리되어 볼이 두 개 날아간다.

도트가 스스로 정하게 넘긴다. 내 포켓몬은 메뉴, 야생 포켓몬은 볼 던지기다
(`WildPet.on_menu`). 야생 도트는 `overlay.pets` 가 아니라 `wild.pet` 에
따로 들어 있어서 찾는 목록에 같이 넣어야 한다.

#### 클릭하면 도트가 눌린 채로 굳었다

같은 이유로 '뗐다'(`ButtonRelease`)도 못 받는다. 원래는 누르고 있는
동안만 멈추는 동작인데, 뗀 것을 못 받으니 그 자리에 영영 서 있었다.
맥에 "지금 눌린 단추가 있냐" 를 직접 물어서 없으면 풀어 준다
(`App._unstick`).

#### 노트북을 닫았다 열면 제자리에서 고개만 흔들었다

닫았다 열면 화면 구성이 바뀐다(외장 모니터가 붙었다 떨어진다). 활동
영역도 같이 바뀌는데, 그때 도트가 새 영역 **밖에** 남는다. 예전 코드는
튕기기만 했다.

    if nx < 왼쪽 or nx > 오른쪽:   vx = -vx;  return

`vx` 를 뒤집어도 여전히 밖이라 다음 틱에 또 튕긴다. 60틱을 돌려 보면
**한 번도 안 움직이고 방향만 60번 뒤집는다.** 화면에서는 제자리에서
좌우로 고개를 흔드는 것으로 보인다.

밖에 있으면 먼저 `clamp()` 로 데려오고, 튕기는 것도 **나가는 쪽으로 갈
때만** 하도록 고쳤다 (`test_walk_bounds.py`).

**맥만의 문제가 아니다.** 윈도우에서도 해상도를 바꾸면 같은 일이 난다.

#### 휠이 안 먹었다

**맥은 휠 한 칸이 `delta=1` 로 온다.** 윈도우는 120 이다. 코드가
`int(-delta / 60)` 이라 맥에서는 몫이 **0** 이 되어 아무 일도 안 했다.
화면은 멀쩡해 보이는데 굴러가지만 않아서, 스크롤바를 손으로 끌기
전까지는 목록이 그게 다인 줄 안다.

`ui_common.wheel_units` 가 '몇 칸인가' 로 먼저 바꾼 뒤에 나눈다. 120
언저리로 오면 윈도우 관례로 보고 나누고, 작게 오면 그대로 칸수로 친다.
윈도우에서 굴러가는 정도는 한 줄도 안 바뀐다(`test_wheel.py` 가 그걸
못박는다).

### (5) 한 번 죽으면 다음부터 안 뜬다 — 제일 고약했던 것

**[확인함]** 프로그램이 비정상 종료되면 맥은 다음 실행 때 "이전에 열려
있던 창을 복구할까요?" 대화상자를 띄운다. 그런데 이게 **`tk.Tk()` 안에서**
뜬다. 스택이 이렇다.

```
TkpInit -> ... -> promptToIgnorePersistentState -> NSAlert runModal
```

`tk.Tk()` 가 거기서 멈춰 선다. 이 프로그램은 **컴퓨터를 켤 때 자동으로
시작하는** 것이라, 한 번 죽고 나면 그 다음 부팅부터 아무 소리 없이 안
뜨고 사용자는 이유를 알 길이 없다.

`platform_mac.before_tk()` 가 `ApplePersistenceIgnoreState` 를 켜서 아예
안 물어보게 한다. 우리는 복구할 창이 없다 — 창은 전부 우리가 다시 만든다.
`app.py` 가 `tk.Tk()` **직전에** 부른다.

(개발 중에도 만난다. Tk 프로브를 몇 번 죽이면 그 뒤로 맨 `tkinter.Tk()`
조차 멈춘다. 그럴 때는 화면에 떠 있는 크래시 보고 창을 닫으면 풀린다.)

### (5-1) 창을 띄울 때마다 쓰던 앱의 포커스를 뺏었다

풀숲이 돋거나 야생 포켓몬이 나올 때마다 앞에 있던 앱의 포커스가 풀렸다.
글을 쓰다가 커서가 사라지는 식이다.

범인은 Tk 이다. 새 창을 화면에 올릴 때 `activateIgnoringOtherApps:` 를
부른다. 재현해 보면 창을 만든 직후가 아니라 **`update()` 에서** 넘어간다.

    창 만든 직후     isActive=False  맨앞=Safari
    raise_above 뒤   isActive=False  맨앞=Safari
    update 뒤        isActive=True   맨앞=Python   <- 여기

바탕화면에서 도트가 걸어다니는 프로그램은 스스로 앞으로 나오면 안 된다.
`platform_mac.keep_focus()` 가 그 메서드를 TKApplication 에 덮어써서
통째로 막는다.

막고 나면 **우리도 못 나온다.** 로그인 창에 글자를 못 치게 되므로 다른
문이 필요하다. 다행히 맥에는 인자 없는 `activate` 가 따로 있어서
(macOS 14 부터) 그쪽은 막힌 문을 지나간다 — `activate()` 가 그걸 쓴다.
창을 여는 자리(`App._tab`, `show_login`, 트레이 메뉴 항목)에서 직접
부른다.

> 원래 구현을 살려 두고 문지기만 세우려고 메서드 맞바꾸기(swizzle)도
> 해 봤지만 안 먹었다. 통째로 막고 다른 문을 내는 편이 확실하다.

> **주의**: macOS 14 부터는 사용자가 만진 적 없는 앱이 스스로 앞으로
> 나오지 못한다. 그래서 `activate()` 는 트레이를 누른 직후처럼 사용자
> 조작 뒤에만 실제로 먹는다. 그게 맞는 동작이기도 하다.

### (5-2) `transient` 를 걸면 창이 사라진다 — 1.0.13 의 새 창 셋이 안 떴다

1.0.13 에 '새로운 기능' 창, 새 버전을 묻는 창, 받는 창이 들어왔는데
**맥에서는 한 번도 안 떴다.** 검사는 다 초록이었다 - 크기만 쟀지 보이는지는
안 봤기 때문이다. 묻는 창은 `wait_window` 로 답을 기다리니, 켜 둔 채로
갈아타는 흐름도 그 자리에서 조용히 멈춰 있었다.

원인은 한 줄이다.

    self.win.transient(self.root)

우리 root 는 withdraw 돼 있다(창은 전부 Toplevel). **맥 Tk 은 withdraw 된
창의 transient 를 같이 withdraw 한다.** 걸자마자 사라지고, 풀어도 그대로다.
맥만 그런 줄 알았는데 **윈도우 러너에서도 똑같이 나왔다**(state=withdrawn
viewable=0). 윈도우는 transient 를 그대로 두고 바로 `deiconify` 로 도로
꺼낸다 - 딸린 창(작업 표시줄에 안 뜸)이라는 관계는 남는다.

    만든 직후                  normal    viewable=1
    transient(withdrawn root)  withdrawn viewable=0
    transient 풀어도            withdrawn viewable=0
    그 뒤 deiconify            normal    viewable=1
    transient 없이             normal    viewable=1

transient 가 주는 것(작업 표시줄에 따로 안 뜸)은 맥에 애초에 없다. 그래서
`PLAT.own_dialog(win, root)` 로 감쌌다 - 윈도우는 transient + deiconify,
맥은 아무것도 안 한다. 허브(탭 창)가 여태 멀쩡했던 것은 transient 를
안 걸었기 때문이었다.

**앞으로 오는 것은 별개 문제다.** 맥 14 부터 앱이 스스로 앞으로 나오는
것은 부탁(cooperative activation)이라, 사용자가 방금 우리를 눌렀으면
(트레이 메뉴) 들어주고 타이머가 띄운 창이면 거절한다. 거절돼도 새로 연
창은 보통 층의 맨 앞에 온다 - 재 보니 파인더가 활성인 채로 우리 창이
순서 0 이었다. 키보드만 쓰던 앱에 남는다. 그 정도가 맞다.
`PLAT.surface(win)` 이 그 부탁을 한다. `-topmost` 는 일부러 안 건다 -
글 읽는 창이 닫을 때까지 브라우저 위에 떠 있으면 그게 방해다.

`smoke_new_windows.py` 가 이제 창이 **보이는지**(state·viewable)도 본다.
root 를 withdraw 한 채로 돌리니 앱과 같은 조건이고, 맥 러너에서 잡힌다.

### (6) 맥에서 윈도우 exe 를 받아 실행하려 든다

**[확인함]** `app.check_update()` 의 유일한 관문이 `updater.is_frozen()`
이었는데, 맥 `.app` 도 `sys.frozen` 이 True 다. 그리고 예전 `check()` 는
`.zip` 으로 끝나는 첫 번째를 그냥 집었다 — 운영체제를 안 봤다. 막지
않으면 맥에서 켤 때마다 윈도우 zip 을 받아 `.app` 번들 안에 풀고 `.exe`
를 실행하려다 실패하는 짓을 반복한다.

**지금은 맥도 자동 업데이트를 한다.** 세 가지를 같이 고쳤다.

  · `pick_asset()` 이 운영체제별로 고른다. 맥은 `.dmg`, 윈도우는 `.zip`
    이되 이름에 `-mac` 이 든 것은 집지 않는다.
  · `_mac_extract()` 가 dmg 를 붙여 `.app` 을 **`ditto` 로** 꺼낸다.
    zip 풀듯 하면 심볼릭 링크와 실행 권한이 날아간다.
  · `_mac_relaunch()` 가 갈아끼운다. **돌고 있는 번들은 그 자리에서 못
    바꾸므로**, 우리가 끝나기를 기다렸다가 바꾸는 작은 스크립트를 띄워
    두고 물러난다.

갈아끼우기는 실패하면 앱이 통째로 사라질 수 있는 일이라, 있던 것을 먼저
옆으로 옮기고 새것을 넣은 뒤에 지운다. 중간에 어긋나면 되돌린다.
`test_update_mac.py` 가 **일부러 실패시켜서 앱이 그대로 남는지**까지 본다.

### (7) 자동 시작 — `launchctl bootout` 은 자기 자신을 죽인다

**[확인함]** 맥은 `~/Library/LaunchAgents` 에 plist 를 두면 로그인할 때
launchd 가 띄운다.

흔히 쓰는 `launchctl bootout` + `bootstrap` 조합을 **쓰면 안 된다.**
`bootout` 은 그 잡의 프로세스에 SIGTERM 을 보내는데, 자동 시작으로 켜진
우리가 바로 그 잡이다. 설정에서 체크를 끄면 그 자리에서 앱이 사라지고,
앱을 옮겨서 경로를 다시 쓸 때도, 로그아웃·탈퇴 때도 똑같이 죽는다.

그래서 **파일만 쓰고 지운다.** 지금 세션에 잡을 올릴 이유도 없다 —
우리는 이미 돌고 있다. 이 규칙을 다시 깨뜨리지 않도록 검사를 하나 두었다
(`test_autostart_mac.py` 의 "끌 때 launchctl 을 부르지 않는다").

**[확인함]** launchd 가 우리가 쓴 plist 를 받아들이고, `--autostart`
인자와 `POKET_AUTOSTART` 환경변수를 그대로 넘겨준다는 것까지는 확인했다
(검사용 레이블로 bootstrap 해서 확인하고 지운다).

**[눈으로 봐야 함]** 실제로 **로그아웃했다가 다시 로그인했을 때 뜨는지**는
확인 못 했다. 한 번 해 보고 안 뜨면 시스템 설정 > 일반 > 로그인 항목을
봐라.

**[눈으로 봐야 함]** 사용자가 **로그인 항목에서 껐을 때** 우리가 알아채는
지도 확인 못 했다. 맥은 그 결정을 launchd 의 disabled 목록이 아니라 다른
곳(BTM)에 적는데, 우리가 읽을 수 있는 것은 `launchctl print-disabled`
뿐이다. 그래서 `blocked()` 는 **"꺼져 있다" 는 확실히 알지만 "켜져
있다" 는 단정하지 않는 쪽**으로 틀리게 해 두었다. 잘 되고 있는 것을
"꺼졌다" 고 말하는 쪽이 더 나쁘기 때문이다.

## 5. 빌드

```bash
pip install pyinstaller
python tools/build_app.py
```

결과는 `dist/포스크탑.app` 과 `dist/poketdesktop-vX.Y.Z-mac.dmg` 이다.

윈도우 쪽(`build_exe.py`)과 다른 점:

- `--onefile` 을 안 쓴다. 맥에서 배포하는 단위는 **번들 폴더**다.
- 아이콘이 `.icns` 다 (`iconutil` 로 만든다).
- **`.zip` 이 아니라 `.dmg` 로 낸다.** 맥에서 익숙한 형태이기도 하지만,
  진짜 이유는 따로 있다. 윈도우 클라이언트의 자동 업데이트가 릴리스
  자산에서 **`.zip` 으로 끝나는 첫 번째**를 운영체제도 안 보고 집는다
  (`updater.check`). 같은 릴리스에 맥 zip 을 올리면 옛 버전을 쓰던
  윈도우 사용자가 그걸 받아서 "실행 파일을 찾지 못했습니다" 로 끝난다.

  **실제로 그렇게 된다.** 깃허브 API 는 자산을 이름순으로 준다.
  `poketdesktop-v1.0.8-mac.zip` 은 `poketdesktop-v1.0.8.zip` 보다
  **앞에** 온다(`-` 가 `.` 보다 작다). 그러니 맥 zip 을 올리는 순간
  윈도우 사용자가 그걸 먼저 집는다. 이미 나가 있는 클라이언트는 고칠 수
  없으니, 자산 이름이 `.zip` 이 아니게 두는 것이 유일하게 확실한 방법이다.

  번들을 옮길 때는 **`ditto`** 를 쓴다. `cp -R` 이나 `shutil` 은 번들 안의
  심볼릭 링크를 따라가 실체로 복제해서 프레임워크를 깨뜨린다.
  (v1.0.8 dmg 안에 심볼릭 링크가 63개 살아 있는 것을 확인했다.)
- dmg 안에 `/Applications` 바로가기를 같이 넣어서, 받는 사람이 끌어다
  놓기만 하면 되게 한다.
- pystray 대신 pyobjc 를 hidden import 로 넣는다.

**빌드 로그에 `Error while signing the bundle ... --deep` 이 보여도 대개
괜찮다.** 그건 번들 바깥쪽을 한 번 더 서명하려다 실패한 것이고, 안쪽
실행 파일에는 임시 서명이 이미 붙어 있다. (`codesign --deep` 은 이렇게
겹겹이 든 번들에서 재귀가 너무 깊어져 스스로 죽는 일이 있다 — 이 맥에서
실제로 죽었다.) 빌드 스크립트가 끝에 서명 상태를 확인해서 알려준다.

**서명이 아예 없으면 애플 실리콘에서는 실행 자체가 막힌다.** 없다고
나오면 `--deep` **없이** 다시 서명해라.

```bash
codesign --force --sign - 'dist/포스크탑.app'
```

**임시 서명만으로 배포하면 받는 사람은 앱을 그냥 못 연다.** 인터넷에서
받은 파일에 맥이 붙이는 격리 표시 때문인데, 개발자 서명이 없으면 이렇게
막는다.

    "포스크탑"은(는) 손상되었기 때문에 열 수 없습니다.

**"확인되지 않은 개발자" 경고가 아니라 아예 막는 것이라, 우클릭 → 열기
로도 안 넘어간다.** 그래서 배포판은 서명하고 공증까지 받는다 — 다음 장.

## 5-1. 서명과 공증 — 경고를 아예 없애려면

받는 사람이 아무 말 없이 두 번 눌러 열게 하려면 **개발자 서명과 공증**
둘 다 필요하다. 하나만 해서는 안 된다.

빌드 스크립트는 준비돼 있다. 인증서가 키체인에 있으면 알아서 서명하고,
공증 자격증명이 있으면 공증까지 받는다. 없으면 임시 서명 판이 나온다.

### 한 번만 해 두면 되는 것

1. **Developer ID Application 인증서를 만든다.**
   [developer.apple.com](https://developer.apple.com/account/resources/certificates)
   → Certificates → **+** → **Developer ID Application**.

   > **Apple Development 는 안 된다.** 그건 Xcode 로 내 기기에서 돌릴 때
   > 쓰는 것이라 남에게 준 앱은 그대로 막힌다. 이름이 비슷해서 헷갈린다.
   > 유료 계정(연 $99)이 있어야 하고, 팀의 Account Holder 여야 만들 수 있다.

   받은 `.cer` 를 두 번 눌러 키체인에 넣는다. 확인:

   ```bash
   security find-identity -v -p codesigning | grep "Developer ID"
   ```

2. **공증용 암호를 만든다.**
   [appleid.apple.com](https://appleid.apple.com) → 로그인 및 보안 →
   **앱 암호** 에서 하나 만든다. 애플 ID 본 암호가 아니다.

3. **자격증명을 저장한다.**

   ```bash
   xcrun notarytool store-credentials poketdesktop \
     --apple-id <애플ID> --team-id <팀ID> --password <앱 암호>
   ```

   그 다음부터는 이렇게 쓰면 서명·공증·박아넣기까지 한 번에 된다.

   ```bash
   POKET_NOTARY_PROFILE=poketdesktop python tools/build_app.py
   ```

### CI 에서 하려면

위까지는 **내 맥에서 빌드할 때** 이야기다. 태그를 밀어서 GitHub Actions
가 빌드하게 하려면 러너에게도 같은 인증서를 줘야 한다. 러너는 매번
새 맥이라 키체인이 비어 있다.

넣을 것은 다섯이다. **하나라도 없으면 워크플로가 서명을 조용히 건너뛰고
임시 서명 판을 낸다** (빌드는 성공하고, 받는 사람만 막힌다).

| 이름 | 무엇 |
|---|---|
| `MACOS_CERT_P12` | 인증서를 `.p12` 로 내보내 **base64 로 바꾼 것** |
| `MACOS_CERT_PASSWORD` | `.p12` 를 내보낼 때 정한 암호 |
| `MACOS_NOTARY_APPLE_ID` | 애플 ID |
| `MACOS_NOTARY_PASSWORD` | 위 2번에서 만든 **앱 암호** |
| `MACOS_NOTARY_TEAM_ID` | 팀 ID (10자리) |

> 앱 암호는 `notarytool store-credentials` 로 키체인에 넣어 뒀더라도
> **CI 에는 값 자체를 넣어야 한다.** 키체인에 든 것은 이 맥에만 있다.
> 그때 적어 둔 것이 없으면 appleid.apple.com 에서 새로 만들면 된다
> (옛 것은 지워도 되고 놔둬도 된다).

#### `.p12` 만들기

키체인 접근에서 **인증서와 개인 키를 같이** 골라야 한다. 인증서만
내보내면 서명을 못 한다.

1. **키체인 접근** 을 연다 (`⌘Space` → `키체인 접근`).
2. 왼쪽에서 **로그인**, 위 탭에서 **내 인증서**.
3. `Developer ID Application: ...` 왼쪽 **▶ 을 펼쳐** 개인 키가 딸려
   있는지 본다. 없으면 그 인증서로는 서명이 안 된다.
4. 그 줄을 우클릭 → **"Developer ID Application: ..." 내보내기**.
5. 형식 **개인 정보 교환(.p12)**, 바탕화면에 저장.
6. **암호를 정한다.** 이게 `MACOS_CERT_PASSWORD` 다. 그 다음 맥
   로그인 암호를 한 번 더 묻는데, 그건 키체인을 여는 것이라 다르다.

#### 넣기

`gh` 로 넣으면 값이 화면이나 기록에 안 남는다.

```bash
base64 -i ~/Desktop/certificates.p12 | gh secret set MACOS_CERT_P12
gh secret set MACOS_CERT_PASSWORD      # 5번에서 정한 암호를 친다
gh secret set MACOS_NOTARY_APPLE_ID
gh secret set MACOS_NOTARY_PASSWORD    # 앱 암호 (xxxx-xxxx-xxxx-xxxx)
gh secret set MACOS_NOTARY_TEAM_ID
```

넣고 나면 `.p12` 는 지운다.

```bash
rm ~/Desktop/certificates.p12
```

> **`.p12` 와 암호는 저장소에 넣지 마라.** 이 둘을 쥐면 남이 우리 이름
>으로 서명할 수 있다. Secrets 는 로그에도 `***` 로 가려져 나온다.

#### 워크플로가 하는 일

`서명 준비` 단계가 그 실행에서만 쓰는 키체인을 따로 만들어 인증서를
넣는다. 러너의 기본 키체인은 안 건드리고, 실행이 끝나면 통째로 사라진다.

**여기서 두 줄이 중요하다.**

- `security list-keychains -d user -s build.keychain ...` —
  **기본 키체인으로 정하는 것과 "찾아보는 목록" 에 넣는 것은 다른
  일이다.** 목록에 안 넣으면 인증서를 제대로 넣어도 `find-identity` 가
  빈손으로 오고, 서명이 조용히 임시 서명으로 떨어진다.
- `security set-key-partition-list ...` — 이게 없으면 codesign 이
  키를 쓸 때 암호를 물으며 멈춰 선다. 러너에는 답할 사람이 없으니
  타임아웃까지 그대로 서 있는다.

잠금 시간은 안 준다. 공증을 기다리는 몇 분 사이에 키체인이 잠기면
그 뒤 서명이 같은 이유로 멈춘다.

#### 됐는지 확인

태그를 밀고 나서, 올라온 dmg 를 **받아서** 본다. 만든 자리에서 열면
격리 표시가 없어서 잘 되는 것처럼 보인다 (아래 인용 참고).

```bash
spctl -a -vvv -t open --context context:primary-signature 받은.dmg
```

`source=Notarized Developer ID` 가 나와야 한다.

---

> **여기서 한 번 속았다.** 직접 만든 판을 그 자리에서 실행하면 격리
> 표시가 없어서 잘 된다. 그래서 만드는 쪽에서는 이 문제가 안 보이고,
> 리드미에 "우클릭 → 열기" 라고 적어 두었다가 **실제로 받아서 연 사람
> 에게서** 틀렸다는 것을 알았다. 격리를 손으로 붙여서 재현했다.
>
>     붙인 뒤   -> 안 열림 (받은 사람이 겪는 그대로)
>     xattr 로 뗀 뒤 -> 열림
>
> **그 다음엔 서명이 안 붙어서 또 한참 걸렸다.**
> `codesign --verify --strict` 가 `a sealed resource is missing or
> invalid` 만 되풀이했다. 프레임워크가 양쪽에 있는 구조 탓인 줄 알고
> 안쪽부터 다시 서명해 봤지만 그대로였다. 원인은 딴 데 있었다 —
> **실행 파일 이름이 한글이었다.**
>
> 맥은 파일 이름을 NFC(조합형)로 저장하는데 codesign 은 번들에서
> NFD(분해형)로 실행 파일 경로를 얻는다. 둘이 문자열로 안 맞으니
> `Contents/MacOS/포스크탑` 을 **주 실행 파일로 알아보지 못하고**,
> 봉인에서 빼는 대신 자원 목록에 cdhash 로 박아 넣은 다음, 바로 그
> 자리에 서명을 써서 **방금 박은 해시를 스스로 무효화한다.** 한 번의
> codesign 안에서 나는 자기모순이라 **서명 순서를 어떻게 바꿔도
> 안 고쳐진다.** 파일 5개짜리 최소 앱으로 좁혀서 확인했다.
>
>     실행 파일 이름   NFC/NFD 가 다른가   codesign --verify --strict
>     poketdesktop     아니오              통과
>     日本語           아니오(정준분해 없음) 통과
>     my app           아니오              통과
>     café             예                  실패
>     포스크탑         예                  실패
>
> 그래서 `EXEC_NAME = "poketdesktop"` 이다. **보이는 이름은 안 바뀐다** —
> Finder·독·메뉴막대에 뜨는 것은 `.app` 폴더 이름과 `CFBundleName` 이
> 정하고, 그건 `포스크탑` 그대로다.
>
> **`codesign --verify` 는 어느 파일이 문제인지 안 알려준다.**
> verbose=4 를 줘도 한 줄뿐이다. 알아내는 길은 둘이었다 —
> `CodeResources` 를 직접 파싱해 디스크 실물과 대조하거나,
> 그냥 공증에 넣고 `xcrun notarytool log <id>` 를 보는 것.
> **후자가 훨씬 빨랐다.** 어느 파일이 왜 안 되는지 경로까지 짚어 준다.
> 프레임워크를 `Versions/<버전>` 으로 서명해야 한다는 것도 이 로그가
> 알려줬다.

## 6. 검사

**화면 없이 도는 것**

```bash
python client/test_layout.py        # 투기장 좌표 3,294개
python common/test_korean.py        # 시간 표기 70,774개
python client/test_battle_ui.py     # 체력바 22개
python client/test_boot_retry.py    # 부팅 직후 재시도 21개
python client/test_autostart_mac.py # 맥 자동 시작 37개
python client/test_wheel.py         # 휠 한 칸이 몇 줄인가 90개
python client/test_mac_input.py     # 우클릭이 어디로 가는가 14개
python client/test_walk_bounds.py   # 영역이 바뀌었을 때 17개
python client/test_update_mac.py    # 자동 업데이트 25개
```

**화면이 필요한 것** — 창을 잠깐 띄웠다 스스로 끈다.

```bash
python client/smoke_mac.py [도트.gif]   # 투명 배경·도트·이펙트 레이어
python client/test_tray_mac.py          # 메뉴 막대 아이콘과 메뉴
```

`smoke_mac.py` 는 **눈으로 보는 대신 화면에 합성된 결과를 그대로 읽는다.**
자기 프로세스의 창은 `CGWindowListCreateImage` 로 찍을 수 있어서, 도트가
실제로 보이는지 모서리가 투명한지를 숫자로 확인한다. 클릭이 이펙트
레이어를 지나가는지도 창 서버에 직접 물어서 본다.

`test_tray_mac.py` 는 화면을 찍지 않는다. 메뉴 막대 항목은 요즘 맥에서
제어 센터가 대신 그려서 우리 창 목록에 안 나타나기 때문이다. 대신
`NSStatusItem.isVisible()` 과 메뉴 객체의 내용을 확인한다.

**둘 다 화면이 잠겨 있으면 못 한다.** 잠겨 있으면 그렇다고 말하고
그냥 넘어간다 - 잠긴 화면에서는 창이 합성되지 않아서, 그대로 두면
멀쩡한 코드가 전부 실패한 것처럼 보인다.

**윈도우 전용** — 맥에서는 "윈도우에서만 하는 검사입니다" 하고 넘어간다.

```bash
python client/test_autostart.py
python client/smoke_autostart.py
```

**서버 검사** — 도커로 임시 서버를 띄워서 돌린다.

```bash
docker build -f server/Dockerfile -t poket-test .
docker run -d --name poket-test -p 8788:8080 \
  -e POKET_DB=/data/poket.db -e POKET_POKEDEX=/app/data/pokedex.json \
  -e POKET_REQUIRE_IP=0 poket-test
python server/test_social.py http://127.0.0.1:8788
```

`server/test_items.py` 는 지금도 7개가 실패한다. **원래 그렇다** — 야생
배틀 승리를 전제로 하는 검사들이라 환경을 탄다. 맥 때문이 아니다.

## 7. 아직 눈으로 봐야 하는 것

코드는 들어갔지만 사람이 확인해야 확정되는 것들이다. 다르면 이 문서를
고쳐라.

1. **글자 크기가 맥에서 읽을 만한가.** 윈도우 기준으로 맞춘 값이라
   맥에서 작아 보일 수 있다 (`ui_common.init_fonts`).
2. **로그아웃했다 다시 로그인하면 자동으로 뜨는가.**
3. **독을 왼쪽이나 오른쪽에 두었을 때** 활동 영역이 맞는가. 모니터 두 대는
   실제로 겪었고(메뉴가 엉뚱한 화면으로 끌려갔다) 고쳐 두었지만, 독을
   옆에 둔 구성은 아직 못 봤다.
4. **사용자가 시스템 설정 > 로그인 항목에서 껐을 때** 우리가 알아채는가
   (3장 (7)).

### 이건 확인했다

  · **이펙트 레이어는 클릭이 통과한다.** 창 서버에 직접 물어서 보고,
    껐다 켜는 대조 실험까지 `smoke_mac.py` 에 넣었다.
  · **도트 둘레의 빈 자리는 통과하지 않는다.** 눈으로 볼 일이 아니라
    **아직 안 고친 것**이다 — 3장 (1) 의 "잃는 것" 을 보라.
  · **창이 떠도 쓰던 앱의 포커스를 안 뺏는다.** 야생 포켓몬이 나오는
    동안 다른 앱이 맨앞 그대로인 것을 실기로 확인했다 (3장 (5-1)).
  · **자동 업데이트가 돈다.** 1.0.8 번들을 띄워 놓고 지켜보다가 인증서
    문제를 잡았다 (3장 (6)). 갈아끼우기는 일부러 실패시켜 앱이 그대로
    남는 것까지 `test_update_mac.py` 가 본다.
  · **CI 가 윈도우와 맥을 한 번에 낸다.** 태그를 밀면 끝이다
    (`.github/workflows/release.yml`).

## 8. 하지 말 것

- **윈도우 코드를 지우고 맥 코드로 바꾸지 마라.** 둘 다 살아 있어야 한다.
  지금 윈도우에서 쓰는 사람이 있다. 옮긴 뒤에는 윈도우에서 검사를 다시
  돌려서 전부 통과하는지 확인해라.
- **`POKET_HOME` 없이 돌리지 마라.** 실제 계정의 설정과 로그인이 덮인다.
- **운영 서버에 검사를 돌리지 마라.**
- **`launchctl bootout` 을 부르지 마라.** 자기 자신을 죽인다 (3장 (7)).
- **`NSMenu` 를 띄우지 마라.** 상태 아이콘에 붙이는 것도, `tk.Menu` 의
  `tk_popup` 도 마찬가지다. 여는 순간 앱이 죽는다 (3장 (3)).
  뜨는 메뉴는 `ui_common.PopupMenu` 로 그린다.
- **오른쪽 클릭을 Tk 바인딩에 기대지 마라.** 맥에서는 앱이 활성일 때만
  온다. `platform_mac.watch_right_click()` 이 받는다 (3장 (4)).
- **휠 delta 를 그대로 나누지 마라.** 맥은 한 칸이 1 이라 몫이 0 이 된다.
  `U.wheel_units()` 를 써라.
- **objc 콜백 안에서 tkinter 를 부르지 마라.** 같은 이유로 죽는다.
- **바탕화면 위에 뜨는 창을 다시 보여줄 때 `deiconify()` 를 직접 부르지
  마라.** `PLAT.show_again(win)` 을 써라. 맥에서 `deiconify()` 는 '항상
  위' 와 클릭 통과를 **둘 다 푼다** — 그냥 두면 배틀 한 판 하고 나서
  포켓몬이 다른 창 뒤로 가라앉는다. (포켓몬 관리·가방 같은 보통 창은
  '항상 위' 가 아니므로 그대로 `deiconify()` 를 써도 된다.)
- **되는 척하지 마라.** 맥에서 아직 안 되는 것은 화면에서 "아직 안
  됩니다" 라고 말해야 한다.
